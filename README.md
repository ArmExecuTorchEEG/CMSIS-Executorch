# Emulator_Deploy

Run the int8 TinyEEGNet `.pte` on the **Corstone-320 FVP**, Arm's simulator of the same Cortex-M55 + Ethos-U85 that is on the Alif E8.
Fork of [Arm-Examples/CMSIS-Executorch @ hackathon](https://github.com/Arm-Examples/CMSIS-Executorch/tree/hackathon) with our model and a correctness harness. Proves the model is NPU-compatible before we touch a board.

## Input

| | |
|---|---|
| Model | `tinyeegnet_int8.pte` from `Reproduce_Baselines` release `v0.1-baseline` |
| Test vectors | `test_vectors.npz` from the same release, converted to a C array by `tools/npz_to_c.py` |
| Toolchain | VS Code + Keil Studio Pack, CMSIS-Toolbox 2.15, Arm Compiler 6 or GCC, Corstone-320 FVP (Docker on macOS) |

## Output

| Artifact | Content |
|---|---|
| Console log | Per test vector: expected vs actual argmax, max abs logit error |
| `results/fvp_metrics.md` | NPU cycles per inference, CPU cycles, inference time at 400 MHz, `.pte` size, arena bytes |
| `results/op_placement.md` | Which operators ran on Ethos-U85 vs fell back to Cortex-M55 (from the export log) |

## Expectations

| Check | Pass condition |
|---|---|
| Build | Compiles for target-type `SSE-320-U85` with zero warnings in our files |
| Correctness | 20/20 test vectors: same argmax as PyTorch; max abs error ≤ 1 quantization step |
| Delegation | 100 % of conv/linear ops on the NPU; only reshape/softmax may fall back |
| Latency | < 10 ms per inference at 400 MHz (model is tiny; this is a sanity bound) |
| Memory | Tensor arena < 256 KB |

If an op falls back to CPU, fix it in `Reproduce_Baselines` (model change), not here.

## Steps

```bash
git clone https://github.com/ArmExecuTorchEEG/Emulator_Deploy && cd Emulator_Deploy
# 1. Tools: open folder in VS Code, accept Arm Tools Environment Manager install
#    (CMSIS-Toolbox, compiler, CMake, Ninja, FVP). macOS: Docker Desktop running.

# 2. Pull model + vectors from the baseline release
./tools/fetch_model.sh v0.1-baseline        # → model/tinyeegnet_int8.pte, model/test_vectors.npz
python tools/npz_to_c.py model/test_vectors.npz src/test_vectors.h

# 3. Regenerate the AI layer (only if the .pte changed)
#    VS Code: Terminal > Run Task > "Create AI layer"

# 4. Select target: CMSIS view > Manage Solution > target-type SSE-320-U85 > Apply

# 5. Build, then Run. Expected console:
#    ExecuTorch Ethos-U85: tinyeegnet_int8 (N bytes)
#    vec 00  exp 1  got 1  maxerr 0   PASS
#    ...
#    20/20 PASS   npu_cycles=xxxxx  cpu_cycles=xxxxx  arena=xxxxx B

# 6. Record numbers
python tools/parse_log.py build/fvp.log > results/fvp_metrics.md
```

## Layout

```
model/            model.py (TinyEEGNet, mirrors Reproduce_Baselines), .pte, vectors (git-ignored, fetched)
ai_layer/         generated by create_ai_layer.py — do not edit
src/              app_main.cpp (harness: loop over vectors, compare, print cycles), test_vectors.h
board/            starter's board files, untouched
tools/            fetch_model.sh, npz_to_c.py, parse_log.py
results/          fvp_metrics.md, op_placement.md
cmsis-executorch.csolution.yml   target-types: SSE-320-U85 (this repo), DevKit-E8 (used by Edge_Deploy)
```

## Common failures

| Symptom | Cause | Fix |
|---|---|---|
| Op not delegated | Unsupported op (ELU, odd padding) | Change model in `Reproduce_Baselines`, re-export |
| Argmax mismatch on a few vectors | Quantization params differ between export and preprocessing | Regenerate `preprocess_params.json` and vectors together |
| FVP does not start on macOS | Docker not running, or `fvp.sh` path not set in csolution | See starter README §6 |
